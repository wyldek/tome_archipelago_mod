# v0.2.1 beta implementation notes

This patch adds hard talent dependency support to the v0.2 full-catalog build.

## Rule

If a selected tree contains a talent that requires another talent/mechanic to function, the seed adds the required category as a support tree (when necessary) and precollects one rank of the enabling talent. The remaining ranks stay in the randomized item pool.

Support trees are extra. They do not consume `class_tree_count` or `generic_tree_count`.

## Initially reviewed dependencies

- `wild-gift/corrosive-blades` -> `wild-gift/mindstar-mastery` + `T_PSIBLADES` rank 1
- `wild-gift/oozing-blades` -> `wild-gift/mindstar-mastery` + `T_PSIBLADES` rank 1
- `chronomancy/temporal-hounds` -> `T_TEMPORAL_HOUNDS` rank 1
- `psionic/thought-forms` -> `T_THOUGHT_FORMS` rank 1
- `wild-gift/summon-advanced` -> `T_MASTER_SUMMONER` rank 1
- `chronomancy/speed-control` -> `T_TIME_DILATION` rank 1
- `spell/advanced-golemancy` -> `spell/golemancy` + `T_GOLEM_POWER` rank 1

The mechanism is recursive and data-driven through `profiles/wanderer-full.json`.

## Validation

Python test suite: 77 passed, 1 optional Lua-runtime test module skipped when Lupa is unavailable.

The Advanced Golemancy rule may expose a separate native Alchemist-golem initialization dependency during real-game testing. The support rule is correct at the talent/category level, but class-specific hidden state still needs qualification.
